# 巨豹智能体工作区

以 Codex 式会话工作区组织剧本创作，配色参考 `http://192.168.10.36:10618/`：浅灰白底、淡紫选中态、紫色主操作、青绿连接状态。左侧通过最近列表和项目管理创作聊天，中间呈现对话和折叠执行过程，右侧阅读原稿、阶段稿件和交付文件。

## 启动

在仓库根目录双击 `启动巨豹智能体.command`，或运行：

```bash
npm run start --workspace apps/drama-studio
```

启动器先检查端口和服务归属，再构建前端，工作区地址为 `http://localhost:10619/`。运行态使用当前仓库的 `.hermes` 与 `.hermes-runtime`。默认创作服务地址为 `127.0.0.1:10620`：端口空闲时启动新后端；已有服务时，读取本机临时凭证并检查 `/api/status` 返回的 `hermes_home` 是否与当前仓库的 `.hermes` 完全一致，一致才复用，保留正在进行的创作。其他仓库、未知服务或无法确认归属时停止并提示，不结束占用进程。

关闭启动终端会结束本次启动的网页及新建后端；复用的已有后端继续运行，已有会话和文件保留。网页端口 `10619` 已在使用时仍停止并提示，可直接打开已有页面。

已有后端时可指定本机地址，不另起服务：

```bash
npm run start --workspace apps/drama-studio -- --backend http://127.0.0.1:60468
```

开发时使用 `SCRIPT_STUDIO_BACKEND=http://127.0.0.1:10620 npm run dev --workspace apps/drama-studio`。

服务器部署使用独立入口：`scripts/serve.mjs --config <配置绝对路径>` 提供已构建前端和账号边缘服务，`scripts/run-backend.py --config <同一配置>` 启动受凭证保护的 Hermes 后端。部署配置中的 `publicOrigin` 明确指定浏览器访问来源；只有配置此字段后才允许非回环监听。HTTP 与 WebSocket 校验实际 Host 和 Origin，不信任转发头；HTTPS 来源对应的会话 Cookie 使用 `Secure`。服务器运行使用 `nativeRuntime` 指定的预装 Python、模块路径和工具目录，账号准备、模型目录读取等请求不会触发 PM 自动同步；不传该配置时保留本机启动流程。

`192.168.10.36` 的目录、`systemd --user` 单元、配置字段及升级回滚步骤见 [服务器部署与运行说明](DEPLOYMENT.md)。本机启动器与服务器入口分开使用，服务器不运行 Vite 开发服务。

## 项目与聊天

登录后先显示工作区，首次连接和模型目录在后台加载，等待时可以输入创作需求；发送和上传在必要数据就绪后开放。历史会话恢复与模型列表并行，只有实际打开已有会话时显示“正在打开创作记录”。加载期间主动切换的聊天和新输入的草稿不会被迟到的自动恢复覆盖。

侧栏“项目”标题右侧的加号用于创建项目，每个项目行内的加号用于在该项目中新建聊天。顶部“新的创作”和 ⌘N 跟随当前选择：未选择项目时，新聊天进入“最近”；选中项目时，新聊天归入该项目。点击“最近”可退出项目选择，项目行内的加号始终在指定项目创建聊天。一个项目可以包含多段独立会话，已有聊天保持原有身份和上下文。上传原稿或首次发送创建会话后，侧栏立即根据真实创建回执显示新对话及项目数量，不等待第一轮生成完成；历史列表随后返回同一会话时合并为一条，标题更新、删除和退出账号同步清理对应状态。

新对话使用显式的无项目归属标记，刷新后仍显示在“最近”；旧版缺少归属标记的聊天保留在原默认项目。最近和每个项目分别保留未发送草稿。项目名称、置顶、隐藏状态和聊天归属按账号持久保存于 `.hermes/studio/sidebar.json`，聊天记录继续使用各账号的 Hermes 会话存储。首次发送或上传原稿创建会话后，先保存其项目归属，再继续执行；归属保存失败时保留原会话并提示重试，不另外创建重复会话。创建项目也使用请求标识保证重试幂等，用户再次主动创建同名项目时仍可产生独立项目。

未发送草稿按项目和聊天在当前页面内暂存，切换项目不会把草稿归到别的项目。移除项目后不再在侧栏显示占位卡片或恢复入口，已有聊天、稿件和草稿的归属保留；在“系统设置 → 已归档”中恢复项目后可继续访问。草稿暂存不等同于刷新页面或退出登录后的持久恢复。

## 模型与思考强度

模型菜单按文字模型与生图模型分组，只显示显示名映射中的名称。新聊天默认使用映射中的首个文字模型，也可选择其他已接入模型；已建立的会话保持其模型。新建聊天时刷新模型目录，使其他账号能看到超级管理员新增的接入。

模型旁的“思考强度”菜单只提供服务端为当前模型和服务声明的可用档位，界面显示“低”“中”“高”等中文名称，请求保留 `low`、`medium`、`high` 等实际值。模型不支持或尚未声明档位时不可调节；切换模型时清除不兼容的选择。新会话通过 `session.create.reasoning_effort` 设置，已有会话通过 `config.set` 的 `reasoning`、`scope: session` 设置，只作用于当前会话。前端和后端都禁止生成中修改，保存完成后从下一轮生效，并使用服务端返回的状态校准显示，不改写全局默认值或历史消息。

只有 `super_admin` 可以在“系统设置 → 模型接入”新增或编辑 API Key、服务地址、模型列表和默认模型。`admin` 和 `employee` 没有入口，直接调用管理接口也返回 `403`；他们可以使用已接入模型和本会话的思考强度设置。当前支持 OpenAI 兼容的 Chat Completions（`chat_completions`）与 Responses（`codex_responses`）两种协议。

密钥保存使用 Hermes 现有凭证存储，读取接口只返回是否已配置，编辑时不回显原密钥；保留同一地址且密钥留空时沿用原值，更换地址需要重新填写密钥。“检查连接”只读取供应商 `/models` 目录，能够验证目录访问，不代表已验证生成、工具调用或完整创作流程。保存接入后同步员工可用模型配置，正在进行的聊天保持当前模型。

## 并发与子智能体

不同聊天可以同时执行；同一聊天按轮次执行，不并行写入两轮上下文。当前页面在生成时提供停止操作，不开放额外的消息排队入口。Hermes 底层另有忙时排队、纠正和中断机制，具体行为由 `display.busy_input_mode` 控制。

每个非超级管理员账号使用独立工作进程。员工模型代理按账号最多同时执行 **10 个模型请求**，同账号的所有聊天、子代理、接入服务和独立审核共享名额；其余请求按先后顺序排队，最多等待 40 项，每项最多等待 120 秒。队列满时返回明确的过载提示，供应商限流则保留独立错误类型及重试等待时间。账号撤销、模型接入删除或密钥轮换会取消相关等待请求。此限制不适用于超级管理员直接使用的主后端。实际承载能力仍取决于主机资源和供应商限流，默认值不是压测结果。

超级管理员沿用的 `jubao-drama` 创作空间已有原生 `delegate_task` 的实际执行与回执。该工具可以分派独立上下文的子智能体，由 Hermes 管理多轮执行与结果回传；历史调用记录不表示每次创作都会分派，也不表示当前始终有子任务运行。默认委派配置允许最多 10 个并发子任务或后台委派单位、1 层子任务，具体覆盖值读取 `delegation` 配置。

普通管理员和员工也可由主会话按需调用原生 `delegate_task`，进行独立分析、核对和草案分工，无需用户手动启动。子代理继承本账号的模型代理、资料范围与业务工具，不能通过委派参数改变模型路由或增加系统工具，也不能继续委派；正式业务确认交回主会话。单批最多两个子代理，账号的并发模型请求仍受前述代理限制。`drama_review` 继续负责正式结构化独立审稿回执，不由子代理口头结论代替。

## 能力与边界

- 新对话默认正常聊天，普通问答、翻译、讨论、看图和生图直接按默认能力处理。剧本规则不随任务意图自动启用；用户需要先明确调用“巨豹 Agent1 · 适配满血版 V1.1”“巨豹 Agent2 · 适配测试版 V2.1”“巨豹 Agent3 · 适配试用版 V3.0”等主 Agent对应的 skill，也可以独立调用“巨豹 skill · 大纲变剧本”和“巨豹 skill · 去 AI 味”。
- 生图复用 Hermes 原生 `image_generate` 工具和 OpenAI 图片后端，通过独立 `/images/generations` 接口生成，每次一张。超级管理员在模型接入里配置生图模型，图片模型与聊天模型列表分开，成员不接触供应商密钥。当前界面支持文生图、图片预览、下载及历史恢复；不开放参考图片编辑参数。
- 图片结果存入当前账号 `cache/generated/images/`，员工页面只获得账号绑定的文件句柄。请求仍受账号执行队列约束，文件访问、凭证撤销和模型配置轮换沿用原有隔离检查。
- 保留流式回复、公开阶段说明、工具开始/返回、确认卡片和断线重连。页面只展示业务摘要、状态与耗时，不展示内部操作参数和原始日志；历史回执按原工具调用编号恢复。
- “本轮已用”是整轮经过时间，包含模型生成、工具执行与等待确认；优先使用服务端起点，实时结束时冻结。工具耗时标注为“工具累计”，缺少历史耗时或断线期间的准确终点时不虚构数字。
- 对话沿用 Hermes 原生事件顺序：正文逐段流式显示，思考中／已思考、工具摘要、技能加载失败、自我改进回顾和后台完成通知直接显示在对话里；子代理用独立卡片展示任务、模型、进度与结果状态。父轮结束后仍保留正在执行的子代理，并显示“后台任务完成后将自动继续”；续接由 Hermes 后端负责，页面不会另发创作请求。内部推理事件只表示模型活动，不逐字显示内部推理文本。默认回复、说明、剧本及台词使用简体中文，用户明确要求英文或双语时按指定范围切换。当前消息携带语言偏好，不改写历史或正在运行的系统提示。
- 重新打开会话时读取原生子代理快照与事件回放，补回仍在执行的子代理、失败委派和可回放的公开回顾。迟到的快照不会覆盖已完成状态或较新的实时进度；会话切换后旧请求不能写入当前聊天。回顾的恢复受 Hermes 事件回放窗口限制，不承诺后端重启后仍保留未落库的事件。
- 每次正常完成回复后，最新回复下方提供一至五个下一步提示词卡片，普通问答和创作交付都适用。预测只依据当前对话历史、压缩摘要、当前会话已读取的资料和用户已确认的约束；本轮新要求优先，不引入其他对话或项目的记忆。等待选择 A/B/C 方案时直接提供各方案选项，并使用正文中的方案名称；缺少或无法解析建议协议时，先识别当前回复中的明确选项，再提供核对或澄清当前内容的保守建议，不猜测人物、集数、进度或新增执行范围。
- 卡片只在用户主动点击后“直接发送”或“填入编辑”；“推荐”仅表示优先选项，没有倒计时或自动应用。已有草稿、正在生成、后台任务未完成、异常状态和正式确认卡片等待处理时，沿用已有操作保护。建议走当前对话的普通消息链路，不能代答审批；展示协议不进入复制内容或稿件面板。
- 面向用户的说明使用严肃、直接的语言，不使用颜文字、表情符号或装饰性等待文案。旧等待动画只作为在线信号，不累积成进展日志。工具操作使用紧凑摘要，展开可查看业务内容、执行结果和已记录耗时；同一工具开始与返回更新同一条记录。手动向上阅读时不抢回滚动位置。
- 同一时刻只使用一个主 Agent，重新选择时直接替换，下一条发送的消息生效，不弹窗或新建对话。旧稿件与审核进度保持各自归属。独立技能可单独调用，也可与任一主 Agent 叠加；OA6.1 的阶段工具仍仅供 OA6.1 使用。脚本、shell、系统凭证等技术权限请求由桥接服务拒绝，页面不会要求编剧批准命令，也不会自动批准这些权限。实时、恢复和重放遵循同一规则。
- 回复按收到的流式片段立即呈现，生成期间使用流式 Markdown 处理未完成的格式。模型活动、公开阶段回复、正文和工具事件保持原有顺序，不等整轮结束后再批量展示。进度说明是否产生取决于模型的实际公开输出，不用等待动画代替真实说明。
- 项目与聊天行均支持右键和更多菜单。置顶、名称与软归档按账号保存；编辑显示名不更改底层固定会话身份；移除项目后只在设置归档页保留恢复入口。只有超级管理员的 macOS 本机工作区提供 Finder 入口。已移除项目和归档聊天统一位于左下角“系统设置 → 已归档”，可以恢复项目，以及恢复或删除聊天；普通聊天菜单也可删除。删除需确认且不能在创作中执行，消息记录删除后不可恢复，原稿、项目稿件与导出文件保留。

- 使用现有 JSON-RPC 客户端和正式会话、模型、附件、停止及人工确认接口；模型和工作流继续由 Hermes 后端执行。
- 任务范围和故事地区随第一条用户消息发送，后续调整请在对话中说明。台词默认“仅中文”，语言选择随每次发送的消息传给 AI；明确选用双语时按双语要求发送。设置不会改写已经生成的稿件，也不等同于逐句语言校验。已有会话沿用其模型，新创作可以从后端返回的模型列表中选择。
- 原生 `Bot Chat` 仍按原身份恢复，在本工作区显示为“剧本创作工作区”。新建创作产生独立会话，不覆盖已有聊天。
- 消息输入、工具调用及后台原始记录不做破坏性重写；界面隐藏内部上下文包装，附件显示文件名，工具过程以中文摘要折叠。
- 原稿支持点击上传或直接拖入工作区，可同时添加多个 TXT、MD、DOCX、XLSX、CSV、PDF 文件，每个不超过 20 MB。拖入仅添加附件，不自动发送消息；不支持文件夹。上传、切换会话、服务未连接或创作进行中时暂不可添加附件。
- 右侧项目资料从当前会话的真实工具回执恢复；大回执通过既有鉴权文件接口读取。它展示最近保存的阶段记录，不根据模型口头承诺推断完成。
- 生成文件通过后端鉴权下载；对话正文也可打开为文稿并下载 Markdown。没有生成 DOCX/XLSX 时不提供虚构的下载文件。
- GM3.1 每批面向用户的剧本、大纲、档案和项目介绍通过 `drama_agent_document` 保存后自动生成 Word。内部笔记使用 `kind=internal`；同名同内容同类型保存幂等，修改另存版本。导出回执随稿件持久化，正文末尾及右侧资料栏提供真实 Word 下载；导出失败保留正文并可重试。现有 Excel 对照导出保留，叙事大纲另有 Word。Word 采用 A4、宋体及独立段落，内容回读校验不等于 WPS 实机版式验收。
- 稿件预览保留原始换行，按集、章、场次和已有 Markdown 标题组织阅读。原始剧本、分析、改编大纲和正文共用可搜索的章节目录，点击目录在当前稿件内跳转；重复标题各有独立锚点。阅读排版不会修改存储的正文或下载文件；已有表格和代码块继续按原结构显示。
- 三个剧本 Agent 的全局入口统一嵌入 `shared/script-format.md` 的剧本格式：`第03集`、`3-1场  场景名  日/夜  内/外`、人物行、`△`动作段与独立对白。更新该文件时同步三个 `SKILL.md` 的共同格式段。当前消息追加同一规则，已调用 Agent 的旧会话从下一轮生效，不修改历史系统提示或已保存正文。大纲与文章按自身章节和段落展示。
- “在稿件面板阅读”和“创作资料”共用阅读器；聊天和面板都保留单换行。TXT/MD/CSV 使用现有鉴权文本预览，DOCX/XLSX 通过鉴权下载后在浏览器中安全解析可读文字。Office 预览保留段落和单元格换行，原文件仍可下载；PDF 沿用下载查看。截断的文本预览明确提示下载全文，无法解析时保留下载入口。
- 使用独立登录和人员管理。`root` 对应超级管理员，沿用已有 `jubao-drama` 创作空间；管理员和员工新建时分配独立账号标识及 `.hermes/studio-workers/<profile>` 运行目录。不会复制其他账号的会话、原稿或记忆。
- 人员管理支持搜索与统计、创建、编辑、重置密码、停用和启用；超级管理员不能被停用或降权，普通管理员只能管理员工。个人账号支持修改昵称、修改密码和退出。
- 使用用户提供的蓝绿标识和“巨豹智能体”名称；模型、任务范围、地区和语言统一使用自定义菜单。模型菜单支持键盘选择和按可用空间上下展开。
- 本地入口只监听回环地址，密码在 `.hermes/studio/accounts.json` 中以 scrypt 加盐哈希保存。浏览器使用 HttpOnly、SameSite Cookie；后台通用凭证不发送到浏览器，写操作验证同源和 CSRF。
- HTTP 与 WebSocket 统一校验人员账号、profile、会话与文件归属，按工作区实际能力限制接口。开发服务器也拒绝直接读取 `.hermes`、运行环境、缓存和账号存储。
- 管理员和员工通过独立工作进程执行创作：macOS 使用 Seatbelt；Linux 使用固定 SHA256 镜像的 Docker 容器，关闭容器外部网络、移除 Linux capabilities，并设置只读根文件系统和 `no-new-privileges`。Linux 只映射必要代码、Python 运行目录与本账号资料，可信配置、插件及技能以只读方式映射；前端和模型代理经专用 Unix Socket 转发。`ipcRoot` 可指定独立短路径，过长的 Socket 路径会明确报错。工作进程只获得账号限定的代理凭证，供应商 API Key 保留在父进程。隔离不可用或主机不受支持时拒绝启动，不回退到共享主后端。超级管理员仍使用受信任的主后端；这些实现和自动测试不等同于公网或真实模型创作验收。
- 员工接口在服务端投影业务字段；不透明资料句柄绑定账号，不能用于读取配置、原始日志或其他账号文件。后端所有 HTTP/WebSocket 请求需专用服务凭证，匿名根页面不再发放令牌。正式启动使用仅提供构建资产的独立 HTTP 服务，源码、源码映射、依赖和未知路径返回 404；开发服务仅供可信开发者使用。
- 此边界针对只持有网页账号的管理员和普通员工；拥有部署机器的系统账号、管理权限或源码副本的人不在该保护范围。无法证明不存在未知漏洞，也不能保证模型不能猜测底层。开源许可与版权依法保留在源码／软件分发材料中；macOS 更新后需要重跑真实隔离测试。
- 密码更新、账号停用和角色变化使原有登录失效。服务重启后需要重新登录；原账号及剧本资料保留。
- 产品身份模板位于 `extensions/jubao-drama/SOUL.md`。更新后的静态提示在新会话载入，不强制刷新正在进行的会话缓存。

## 2026-10-06 付费与并发验收修复

普通创作会话使用原生正常恢复路径，保留已保存模型和思考档位；恢复与实时事件交错时不以旧快照覆盖新回复，切换会话会先等候该会话的事件重放。消息提交回执不明时保留草稿并暂停再次提交，状态核对完成后继续。资料刷新不会覆盖刚发送的附件或新交付。

正文中的正式导出和图片下载链接使用账号绑定的文件句柄，沿用现有鉴权下载；无效和跨账号路径不能下载。DOCX 与 XLSX 使用兼容 Office 阅读器的包元数据。Excel 人物对照采用 A4 横向、大纲对照采用 A3 横向，横向保留全部列、长表纵向分页并重复表头；正文和表格数据保持原文。

独立审稿读取当前原稿、用户要求、已确认方向和前批末态，检查事实、数字推导及实物的持有与转移机会；旧依据的审稿不能用于新版本。正文不得跳集或提前宣布全剧完成，任一批次退修时不得跳过该批导出。仅审稿与仅导出任务按其范围执行。重做必须明确阶段：新纲重做保留核心与方案，正文重做保留已验收新纲；同名导出保留旧文件并提示换名。

真实小规模验收覆盖四个文字模型、两个生图模型，以及同账号 10 路和 12 路创作请求。该结果用于验证本次限定请求下的运行和隔离，不代表主机或供应商的最大承载能力。流式客户端断开时释放执行名额；上游缺少正式完成回执时返回失败，不把半截正文当作正常完成。


## 要求清单与设定库（2026-10-14 重构）

右侧“创作资料”新增“要求”“设定”两个标签，与“文件”共用同一标签栏。两份资料按侧栏项目保存：同一项目中的多段聊天共享，“最近”里的聊天各自独立。

- **要求清单**：用户在对话中提出的要求，由辅助模型在后台整理，每条附用户原话；原话里找不到的条目不会写入。数字类要求（每集字数、集数、修改范围）同时用于稿件的确定性核验。用户可在“要求”标签中添加、修改、置顶、取消或恢复；智能体不能自行增删。
- **设定库**：作品的权威设定。世界规则、人物、人物关系和关键物件是核心设定，智能体提出新增或修改时会弹出确认卡片，用户同意后才写入；地点、时间线与末态、次要人物、文风和备注由智能体直接记录。每次修改都保留版本，可在“设定”标签查看历史并恢复。
- **创作胶囊**：启用主 Agent 或独立技能后，每轮都把生效要求、核心设定、与本轮相关的其他设定和最近末态附在当前消息中，只作用于本次请求，不写入历史；压缩历史后也不会丢失。独立审稿额外对照设定库，正文出现未经确认的新核心设定判为需修改。
- **上下文**：创作账号在约 16 万 token 时压缩历史并提前裁剪旧工具结果；发给模型的请求中，历史消息的固定规则前缀与 OA6.1 项目完整回执改为精简形式，数据库与资料栏仍保留完整记录。
- 旧会话的持续要求与 OA6.1 项目成果已迁移，标记为“旧会话整理”，可在资料栏确认或取消。迁移脚本见 `extensions/jubao-drama/scripts/migrate_creative_memory.py`。

## 独立技能与主 Agent 调用

输入 `/` 或点击输入区的“调用”可选择主 Agent 和独立技能。主 Agent 同时单选，两个独立技能可以多选。选到其他主 Agent 时直接替换草稿中的选择；下一条消息发送时生效，不弹确认框、不新建对话。旧稿件和审核进度仍属于原 Agent，已启用的独立技能继续生效；同条消息同时调用多个主 Agent 会要求只保留一个。

- “巨豹 skill · 去 AI 味”是统一入口，优先选用原包中适合中文剧本、中文说明稿和人物声音的规则；英文稿件按需读取英文参考。不自动启用学术降检测率或繁体本地化规则，不执行来源包里的安装、推广或脚本命令。旧名称在历史里仍可识别，界面统一显示新名称。
- “巨豹 skill · 大纲变剧本”保留原包的故事设计、制作写法和格式参考。用户已经确定的集数、时长和故事路线优先。与主 Agent 同用时沿用工具统一格式；单独使用时采用原包 0715 格式。叠加巨豹 skill · 去 AI 味不改变所选格式；用户当次明确指定的格式始终优先。
- 两个技能同用时先扩写、再优化表达、最后核对剧情和格式；与主 Agent 同用时保留主流程的审核和确认。
- 技能在当前对话持续启用，可点击标签关闭，下一条发送的消息起停用。新对话从空选择开始。每条消息保存本轮选择快照，长历史只恢复近期消息时仍能展示当前选择；此快照不授予后端工具权限。
- 后端只从当前用户消息开头的明确调用更新选择，忽略模板目录、历史调用和附加上下文；工具层按账号与会话检查已启用的能力。主 Agent 在新消息入口按用户明确选择绑定，模型自行调用另一个主 Agent 的规则仍会被拒绝。能力目录统一来自插件 `capabilities.json`，新账号及工作进程启动时分发相同的完整规则文件。
- 独立技能可以读取账号内的资料、保存新稿件版本和导出；稿件正文经过服务端业务字段投影进入资料面板。

使用例子：

1. 只选“巨豹 skill · 去 AI 味”：上传已有稿件，优化对白和描写，保留原稿格式。
2. 只选“巨豹 skill · 大纲变剧本”：提供已有大纲，按原包 0715 格式扩写指定集数。
3. “OA6.1 ＋ 巨豹 skill · 去 AI 味”：按 OA6.1 流程创作，再优化表达；GM3.1 或 GR4.7 也可这样搭配。
4. “大纲变剧本 ＋ 巨豹 skill · 去 AI 味”：先扩写，再润色，保留 0715 格式。
5. “GM3.1 ＋ 大纲变剧本 ＋ 巨豹 skill · 去 AI 味”：由 GM3.1 管理流程，叠加扩写和润色，沿用工具统一格式。

来源文件的 SHA-256 清单位于 `extensions/jubao-drama/skill-source-manifest.json`。规则内容按需由 `skill_view` 完整读取，选择变化随新用户消息传递，不改写历史消息或运行中的系统提示。


## 统一的 Agent 与 skill 标记

主 Agent、大纲变剧本、巨豹 skill · 去 AI 味共用彩色图标标记组件。选择显示在输入框内，发出后在用户消息上方显示同一套标记；正文只保留用户输入的创作需求。技能选择独立保存在草稿状态中，不再把调用句拼到正文。

每轮选择变更通过消息包装的“本轮能力操作”结构区传递，后端解析固定能力 ID 与启停动作，再沿用现有 `skill_view` 完整规则加载和会话权限检查。用户正文、附件引用、历史回复保持各自用途。旧客户端的消息开头调用句继续兼容，旧记录回显为标记；正文材料中出现同名语句不会被扫描成开关。

选择独立技能后持续作用于当前对话，可以移除；尚未发送的选择与正文一起保存草稿。只选择技能而不输入正文也可以发送。换到另一个对话时恢复该对话自己的草稿与技能，避免跨对话串用。单个主 Agent 的重新选择继续采用直接替换，下一条消息发送时生效。
