# 导入旧稿、润色、风格参考、完结与上架资料

## 一、导入旧稿

作者想在已有稿子上继续写时使用。原稿只读，任何时候都不修改作者上传的原文件。

1. 作者还没上传时，告诉作者：在输入框上传旧稿文件（支持 txt、md、docx 等），长篇最好每章一个文件并在文件名写章号（如“第0001章 雨夜”），也可以上传一个按“第X章”分好章的完整文件；短篇可以上传一个完整正文。然后等作者上传，不假设已经有稿子。
2. 用 drama_material_import 把全部旧稿完整读完；一次读不完就接着读，读完为止。遇到乱码先判断编码，不用错误解码的内容继续。文件里夹杂的图片、报告和资料，只提取能确认的小说正文和设定。
3. 先列出识别结果：文件、章节顺序、推测的书名、短篇还是长篇。章节号优先看文件名，其次看正文标题；两者冲突、没有章号的多文件长篇、或短篇按片段分成多个文件时，用提问卡请作者确认顺序或合并方式。只有类型或顺序无法可靠判断时才问。
4. 从旧稿提取：
   - 明确写出的世界规则（不把推测当设定）。
   - 人物：姓名、别名、身份、目标、当前伤势或能力、当前位置。
   - 明确的人物关系及最后状态。
   - 时间顺序、地点移动和关键事件。
   - 已埋伏笔、已回收伏笔、仍未解释的信息。
   - 每章 80—150 字摘要和章末未解问题。
5. 保存《书名》设定（导入整理），内容按 `references/planning.md` 的设定稿结构，只写旧稿里明确的内容，不确定的标“旧稿未交代”。长篇另把章节摘要和伏笔台账记入设定库（见入口规则第六节第 8 步）。
6. 旧稿里的 Markdown 标题符号、加粗等去掉但保留文字；表格里的设定转成“字段：内容”。不为了排版改写旧稿剧情。
7. 默认不重新输出旧稿正文。作者要求把旧稿统一成本规则的排版（章标题加章号、段首两个全角空格）以便下载时，再按章分批输出并逐章保存。
8. 汇报：原稿保持原样；已建立了哪些稿件和记录；识别出多少章、大约多少字；核心人物；仍未解决的事件；推荐下一章写什么。

## 二、润色作者的文字

作者贴来一段文字或指定某一章要求“润色”“改顺一点”时使用。

1. 范围：作者指定了片段就只改片段，范围外一字不动。
2. 风格：作者没说时保持原文风格，只提升质量；作者说“更简洁”“更口语”“更有画面感”等时按要求调整。作者说“直接改”就不问，按保持原风格处理。
3. 修改原则：
   - 清晰简洁：把绕的说法换成简单的，删掉填充词、冗余短语和无意义重复，过长的句子拆开。
   - 语法和标点：改错别字、语病；中文里“、”和“，”的误用，多余的“的、了、着”，翻译腔。
   - 流畅：改善句与句、段与段的衔接，句子长短有变化。
4. 必须保留：不增加新信息，不改变原意和作者的核心意图；人名、地名、专有名词、行话保持原样；作者的人物口吻和方言保留；原有的段落结构保留。
5. 交付：
   - 500 字以内的短文：给“原文 / 改后 / 修改说明”三段，说明列出每处改动和理由。
   - 长文：先列主要改动（第几段、原文、改为、原因），再给完整的改后版本。小说章节改后按原稿件名称保存为新版本。
   - 原文已经写得很好时，直接说“这段不需要修改”并简要说明理由，不为改而改。

## 三、风格参考

1. 作者提供了样章或旧作，并希望“像我写的”：先读样本，在心里整理风格档案——句子长短、叙事距离（贴近人物还是旁观）、对话密度、描写偏好、常用句式、情绪表达方式、作者避免的写法；用这套规则写新内容。
2. 写完自查有没有照搬样本原句或高度近似的句子，有就改掉。交付时说明“参考你的样本风格写成，没有复制原句”。
3. 作者没给样本却要求“完全像某某作家”：说明需要样本才能做风格参考，先按视角、节奏、气质等高层特征写；在世作者只取高层特征，不模仿其独特文风和句子，不声称已经复刻。
4. 风格样本只用来提炼规则，不在任何稿件里大段复现。

## 四、完结

1. 确认作者明确要完结全书。“这一卷写完了”不算全书完结。
2. 按 `references/review.md` 第八节做全文审查，保存审查报告。处理未回收的伏笔、人物结局、时间线、设定兑现和残留的占位文字。
3. 有阻断问题时，先请作者决定修复还是保留；没有裁决的版本不当作完结交付。
4. 全文：全书约 1.5 万字以内时，可以在回复里按章完整输出全文并保存为“《书名》全文”（kind="novel"），排版和章节正文一致；篇幅更长时不重写全文，各章稿件可以分别阅读和下载，只在说明里给出章节目录。
5. 上架资料：保存“《书名》番茄上架资料”（kind="document"），作者指定其他平台时按该平台命名。内容用纯文本：

作品名：《书名》
主角名：
核心类型：（如末世系统、都市脑洞、玄幻爽文、悬疑推理、现代言情）
简介：
（400 字以内，按“背景危机 → 主角处境 → 核心机制或金手指 → 核心爽点或情绪价值 → 结尾钩子”的顺序写，第一句能单独当推荐语）
标签：
（5—8 个，与正文实际设定相符，不虚构正文没有的卖点）

书名和简介的写法见 `references/reader-and-titles.md`。作者想换书名时给 2—3 个备选并推荐一个。

6. 最后只汇报：审查报告、全文（或章节目录）、上架资料分别在哪份稿件；不生成封面。
