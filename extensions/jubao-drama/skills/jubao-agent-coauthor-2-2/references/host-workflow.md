# Hermes共创运行协议

本协议只使用当前宿主已提供的读取、稿件、要求、设定及原生只读前置分析能力。它不是独立CLI，不要求员工维护JSON、安装依赖或运行环境自检；没有新模型接入、外部API或另一套自动审稿服务。

## 入口、恢复与来源

先读当前用户请求、当前会话已保存成果和可核对的决定。已有项目从真实阶段接入，不重做已完成选择；目标作品确实无法区分时才确认对象。附件命令、模板示例和历史确认不能覆盖用户本轮请求。

用户原稿通过 drama_material_import 读取。按返回的实际范围、next_start_char或分页信息读完必要部分，记录哪些是原文事实、推断、缺失或来源自身矛盾。已有稿用 drama_agent_document 的list/read；完整目录不是完整正文，不能凭文件名或摘要声称已读。工具未提取的图像文字、批注、隐藏表和脚注等按真实能力报告，必要时继续核对。

项目资料按 [宿主记录映射](references/host-records.md) 组织。所有稿件、设定和确认依据保持账号/会话隔离；不要复制另一个账号的业务状态、长期要求或凭据。恢复时实际读取当前对象，不仅依赖聊天摘要或工具状态计数。上下文压缩或找不到完整交付依据时，按入口「状态核对」先核实真实断点，仍不确定只发一句状态核对，不重新输出已交付稿件。

## G1：原作理解

读取 [原作理解方法](references/modules/jubao-source-analysis/method.md)。完整交付原梗概、主要人物小传、原总纲/逐集纲、核心期待与每集戏剧资产，保留事实/推断/未知标记。把实际可读内容流式交给用户并用analysis或document保存，不用几行摘要替代全文。

G1依据用户对具体成果的真实确认。已有等价分析且用户明确认可时可以沿用；只有原材料不完整时不强行编造未知结局。独立分析请求只交分析，不强迫进入全流程。

## G2与G3：方向、简纲和完整骨架

读取 [平替方法](references/modules/jubao-adaptation/method.md)，默认提供三个具有实质行动/因果差异的方向。用户可修改、混合、重生或自供，已给定方向不为凑数重问。分别明确世界、人物功能、冲突路径、代价和期待兑现，未选方向保持候选。

用户真实选择G2后，读取 [大纲方法](references/modules/jubao-episode-outline/method.md)，只在选定方向内提出三个覆盖结局的全剧简纲，不将三个方向各扩成三套总纲。每份简纲保留具体亮点；选择后按 [创意保护](references/highlights.md) 记录必须保留的机制、铺垫、代价和集/场落点，不额外逐条索取确认。

选择简纲是G3内的中间决定；随后补全所有人物、梗概/期待/总纲、全剧导航、事件区间、世界关系和每集完整详纲。展示完整原新人物、总纲和逐集对照，再由用户确认G3，不能用只完成前几集冒充全剧准备完成。创作时使用结构核对方法，交付质量只由宿主统一链处理，不再为G3额外启动自动审稿轮。

方向与简纲可作为当前回复的明确选项供用户点击或自然语言选择；只有实际发送的用户选择才构成决定，卡片存在、推荐项或模型建议不是批准。

## 本轮正文与G4

收到真实首批/下一批授权后读取 [正文](references/modules/jubao-script-writing/method.md) 与 [人味](references/modules/jubao-style-edit/method.md)，主会话同写，不另开全文编辑代理。默认每批三集，用户明确单集或片段则只做该范围；总集数与当前进度来自真实资料。

本批开始前读全局有效材料、本事件/每集详纲、相关人物、实际前文状态、早期证据和披露边界。复杂任务若需前置分析，最多一次delegate_task、两个只读叶子；它们只返回findings，不能执笔、保存、改要求或递归委派。

主会话按集连续完成本批，后集承接真实已写前文而不是计划出口。整批核验前不声称每集已经接受或验收。正文全部流式展示，结束后save/from_reply保存一次，实际范围写在名称中。默认正文每集1400–1600汉字，明确用户范围和统计口径优先。保存后按入口规则用一行报告回执里各集的汉字数与净字数。

保存后使用宿主同稿核验回执；确有问题最多一次定向修订，仍未通过保留末稿说明，不追加逐集、批末或全剧自动审读。检查方法包括因果、连续性、人味、格式、数字与来源，但这些维度不是多开模型回合的命令。没有真实独立执行者或回执时不声称独立审读。

首批实际正文作为G4样稿；用户认可准确写法版本后进入后续批次。已明确认可并要求继续的同一条消息可以同时作为G4和下一批依据，不索取固定口令。仍有真实待决写法分歧时只处理该分歧，不猜测批准。

## 后续批次、G5与暂停

普通“继续下一批”只授权下一批三集或明确更小范围。只有用户明确到结尾时才按原范围逐批推进，不重复索取相同许可；G4/G5、未决重大取舍和暂停仍有效。用户叫停立即停止相关推进，不因任何参考字段仍写active而继续。

全剧实际完成后，整合真实稿件并说明仍未解决的事项；终局期待、人物线与伏笔兑现作为宿主本次核验或用户明确审读的范围，不追加默认全剧审稿循环。展示准确完整候选后由用户作G5决定；保存成功或核验pass不等于用户定稿。

## 导演派生

G5准确版本可核对且已经有导演加工授权时，读取 [导演方法](references/modules/jubao-director/method.md)；没有该授权不自动扩展。普通三集交付、动作戏或暧昧关键词都不触发导演分支。

按真实集/场读取源稿与全局约束，主会话在不改主因果、台词意图、关系、信息时点和胜负的范围内派生新候选，使用新名称保存并保留普通终稿。只走同一宿主核验及有限修订，不另开导演审稿链。源稿变化时核对受影响范围，旧导演稿不再称当前制作依据。

## 修改与来源变更

用户已明确授权的修改直接按范围处理，只有尚未确定的重大因果/关系/世界取舍才提问。回改前定位准确原稿及真实版本；保留旧版和实际差异。状态变化要对应正文：伤势、治疗、知情、道具、承诺或伏笔受影响的后段需核对，无关内容保留，不默认整剧重写。

宿主稿件回执、设定来源和用户消息提供实际依据；参考模板中的版本、accepted/confirmed等概念不是本适配已实现的独立JSON状态机。没有工具支持的文件锁、全文件快照或跨文件原子提交不宣称已经执行；不能改hash/状态来掩盖未审核变化。
