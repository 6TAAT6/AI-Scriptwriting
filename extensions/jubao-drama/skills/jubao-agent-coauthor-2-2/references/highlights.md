# 创意从简纲到正文的保留

本方法由当前Hermes主会话在已授权设计与写作中运用，不启动额外审稿或第六个确认节点。

每个简纲同时给出完整路线和具体亮点：事件如何发生、精彩点在哪里、依赖什么铺垫、人物付出什么代价。数量随故事需要，不凑配额；简纲不能只写“反转、爽点、虐点”。

用户选择/修改简纲时，记录必须保留、允许调整、不采用的亮点。未明确标记的内容按所选方案与用户表达解释，不机械新增逐条询问。把有效亮点整理为宿主实际保存的“创意亮点与落点”资料，每项有短 ID、具体机制、选择依据、必要条件、预定集/场、允许变化范围。这个文件记录设计，不记录正文已经实现。

深化详纲时，建立选中亮点的铺垫→行动/反制→结果→后果。对每项标明详纲落点。可以丰富细节，但不悄悄改成另一种普通解决方式。原作保留的是戏剧目的/情绪/卡点；这里保护的是新方案被选中的创意，不把原作事件原样搬回。

G3的真实确认对象包含这份亮点资料；正文和导演任务按实际相关范围完整读取，不声称原包全文件快照或脚本资料包已经运行。正文作者保留亮点机制和必要前提，发挥对白、动作、停顿、临场反应和幽默。不能把智斗过程缩成旁白宣布获胜。

审稿报告说明本集涉及哪些亮点，实际在哪个场/段演出，有没有被省略或替换。没有本集落点也明确说明，不为了填表强造反转。内容版本采用宿主实际回执；语义兑现纳入宿主同一核验或用户明确请求的审读，不另开自动复审。

例如：故意说错密室内细节，诱使声称未进过密室的对手纠正。若改成路人送录像直接证明，揭露结果保留但智斗机制消失，应按是否属于用户保留项处理。更好改法可比较收益、代价与下游影响后采用；用户已经明确要求的修改不重复求批。
