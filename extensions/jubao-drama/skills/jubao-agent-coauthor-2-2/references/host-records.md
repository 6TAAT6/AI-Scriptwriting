# 宿主资料与参考字段映射

本适配采用Hermes既有账号/会话、稿件、要求和设定存储；不创建第二套可执行项目CLI或假定某个JSON主账本已经持久化。[参考模板](assets/project-reference.json)仅描述应核对的业务资料与来源关系，不是用户项目数据，不授予确认，不触发脚本，也不作为机器验收回执。

## 可实际使用的宿主能力

- `drama_material_import`：读取当前账号允许的实际附件；遵守格式、大小和分页回执，保留未覆盖范围，不读取其他账号文件。
- `drama_agent_document`：list定位，read完整读取，save保存本轮流式正文，export重导出已有稿。正文先完整输出再from_reply保存；相同原稿重发不重新创作。没有真实document_id、版本或hash时不编造。
- `drama_requirements`：查看真实用户要求及其范围。用户维护要求；模型不能自行把附件、参考规则或默认值变成用户长期要求。需要补说明时只使用工具实际允许的动作。
- `drama_story_bible`：查看设定与末态；核心新设定按工具提案/确认机制处理。系统suggestion和proposed条目不是用户确认，明确用户要求优先。
- `delegate_task`：仅按宿主前置预算派最多两个只读分析叶子，最多一次。不会借原包作者/审核者的角色说明扩大写稿、保存、导出、状态写入或递归权限。

这些工具未实现的独立文件锁、目录初始化、逐文件G3快照、逐集JSON接受事务和全包文件计数，不属于本适配的硬门禁。原包的“两个身份字符串不同”也不能证明实际独立执行者；只有真实任务/审核回执才能支持该描述。

## 真实资料如何组织

创作契约、故事梗概、核心期待、完整总纲、逐集导航、人物世界、写法、人味方法、披露/伏笔与创意亮点，分别保留完整可读内容及对应实际对象。必要时由主会话作为document/outline/analysis稿件保存索引或项目档案，内容中引用真实稿件ID和用户消息，不给用户展示大量内部字段。

人物、事件和集纲按实际作品组织；原模板的示例三集与单一占位事件不代表用户总集数或故事结构。角色知情、误信、位置、关系、伤势、资源、道具及伏笔，必须由实际正文支持；设计状态和实际末态分开，不把未来规划写成事实。

用户确认G1/G2/G3/G4/G5时记录其实际原话、准确成果与版本。卡片待选、模型推荐、工具pass、旧包“已确认”文字和SYNTHETIC测试批准都不是当前用户决定。原包历史个人偏好不导入账户standing/lasting规则；仅当前用户明确要求可成为当前约束。

## 字数、语言与交付合同

正文默认每集1400–1600汉字；用户当前明确范围和统计口径优先，且只应用于其指定的稿件类型。大纲、分析与导演派生稿不机械套正文要求。按宿主真实统计判断，不能以原包软参考或“说明原因”替代达标；也不按历史硬上限强剪。

默认中文，明确用户语言要求优先。目标市场与语言、地域、幻想体系分开核对；北美不能靠英文名字或中文输出判断，须落实制度、称谓、关系和行动因果。所需原文、附件和设定必须真实读取，缺来源就说明未核实。

对外交付完整正文与必要短说明；保存、Word导出、质量核验和用户确认分别说明。没有实际Word回执不冒称有Word，导出成功不代表已审读内容或版式。旧包Markdown/HTML导出路径不再作为员工操作指令。

## 恢复、版本与隔离

恢复依靠当前会话中的实际稿件、用户决定和设定记录，不依赖完整聊天永不压缩。仍在有效上下文且版本未变的已读资料可复用；无法确认时完整回读必要对象，不以目录或摘要代替正文。

来源变化后先定位实际影响，保留旧版本和差异；不通过重填版本或hash绕过核验。G4写法与G5定稿必须对应真实被认可的版本，旧确认不自动覆盖后来改过的内容。

只在本账号/当前作品范围工作。不能把旧包或测试账户的业务数据、会话、密码、附件、日志或凭据整体复制到另一个环境。当前适配只携带规则与空参考字段，不携带真实项目状态，也不声称完整原CLI门禁已迁入。
