# 巨豹导演增强

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

本技能在全剧完成且准确终稿版本经用户确认后独立运行。它从主剧本派生导演增强候选，不能替代编剧、提前扩写未定稿故事或覆盖终稿。普通写作、每三集交付及“继续下一批”均不触发导演分支。若用户此前已要求全剧定稿后做导演加工，G5 完成即按该授权衔接，不重复问是否开始；没有该授权时不自动扩展交付。

## 触发与输入

- 全剧 G5 确认后，用户已要求导演加工、动作特效增强或成人非露骨暧昧增强时使用；该要求可以来自此前对定稿后流程的明确安排。普通阶段对既有关系的对白、回应、停顿与必要表演润色仍由写作/人味 skill 处理；不能只凭“加强暧昧”关键词启动本技能。源稿恰有动作戏、暧昧戏或视频制作用途，不构成自动调用。
- 先通过 drama_agent_document 的 list/read 完整读取真实全剧终稿和当前集/场资料，核对用户G5确认的准确版本及已有导演授权。按 [宿主资料映射](references/host-records.md) 关联梗概、期待、总纲、导航、世界、人物、详纲、实际状态与写法；原项目字段只作参考，不虚构JSON状态或确认。保持全剧约束不等于一次把全剧所有正文装入上下文。
- 资料只来自当前账号/会话允许的附件与稿件。源稿身份和内容指纹沿用本次真实read回执，差异说明绑定准确集/场与源版本；不能从技能目录推导业务项目路径，也不伪造哈希。具体读取及返回方式见 [调用与产物契约](references/modules/jubao-director/workflow-contract.md)。
- 原创事实和用户指令优先于参考案例。维护来源注记只解释规则来历，不是运行时必须读取的外部依赖。

## 流程

1. 核对当前或此前已有导演授权的具体范围，并确认G5实际用户消息对应当前全剧版本。通过宿主工具读取实际终稿，采用真实回执的稿件ID与内容指纹；对象不匹配时说明缺口，不把普通写作续批授权转为导演授权。不得以模板字段或文件存在冒充用户确认。
2. 读取 [范围与表演](references/modules/jubao-director/scope-and-performance.md)。逐场先识别戏剧目的、目标/阻碍、情绪与关系变化、信息时点和固定结果，再选择增强手段。分析用于内部工作，用户只要正文时不自动打印分析表。
3. 以完整定稿为权威源，按集/场资料包逐段处理用户指定范围；未指定局部范围时覆盖全剧，但不一次灌入全量正文。通过主档、状态、揭示边界与跨场相关原文检索保持全剧约束。保留主情节、关系、台词意图、信息时点、胜负及其因果，不添加世界机制。动作和情绪提示按需要使用，不强制每句动作、每段七层或每场表演配额。
4. 仅对有相应内容的场戏按需加载参考：打斗、追逐与能力效果读 [动作与特效](references/modules/jubao-director/action-effects.md)；成人非露骨暧昧读 [成年人与暧昧](references/modules/jubao-director/adult-chemistry.md)；声音确有叙事作用时读 [声音](references/modules/jubao-director/sound.md)。不为启用分支新增打斗、能力、暧昧或声源。
5. 做源稿与增强稿的差异核对：集/场顺序、台词及必要微调、人物出入、道具、伤势、能力、信息揭示和胜负。发现主稿问题时，列出位置、影响和修订建议，不在导演稿中偷改。
6. 由主会话流式返回独立派生候选及简短实际变更说明，沿用宿主保存与统一核验链，不覆盖普通终稿、不再追加自动导演审稿。首稿加最多一次范围内定向修订；未核验或未解决越权问题保留候选并说明。技术制作参数仅在需要时另附，不强制摄影机锁。

## 输出与权限

- 正文全部中文，沿用项目已确认的场次、人物、对白、`△` 与 VO/OS 规范；真实换行，不输出工程字段表。VO/OS 按声音身份区分，不能因复制样本而混标。
- 台词默认保留原文。用户已经授权且本次仍有效的局部微调可以直接完成，但必须守住意图、语义范围、信息和关系功能；列明实际改词。不设置“每改一字先审批”。改变含义、信息时点或重大因果的要求属于主稿修订，不由导演增强暗中完成。
- 主会话通过 drama_agent_document 保存当前授权的导演候选，使用清楚的新名称并保留源稿。子智能体仍只读，不写文件、主状态或确认；候选保存权限不代表可以覆盖普通终稿或改变G5。
- 不重复要求已存在且可核对的确认。不新增常规人工门，不把独立导演调用变成新的终稿审批流程。若用户实际要求修改主稿，返回相应任务范围，不冒称导演稿就是新终稿。
- 只报告实际完成的范围与文件。格式校验、内部检查、导演候选生成和用户认可分别记录，不声称已经分镜、制作或平台过审。

## 独立调用与缺资料

没有已保存项目资料时，读取用户实际提供的材料；有可核对的完整终稿和用户对准确版本的确认，可建立仅本次的最小来源约定。只处理某场时，使用用户明确给出的已定稿范围、必要上下文与固定结果，说明未核查的跨场边界，不强索整部正文。候选通过宿主工具保存，不虚构G5或原文件状态机已经登记。

全剧任务缺少完整终稿，或任何任务缺少其源稿属于已确认全剧版本的依据时，指出实际缺口并请求必要材料；可先做现有材料的范围/连续性诊断，不声称已经开始全剧导演转换。缺摄影机参数、某条库模板或无关生产资料不构成阻断。参考 [调用与产物契约](references/modules/jubao-director/workflow-contract.md) 中的独立调用规则。
