# 中文短剧正文创作

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

把已确认的新故事写成角色有欲望、对白有交锋、事件有因果、前后能承接的中文正文。事件负责因果连续，分集负责情绪和卡点，批次负责交付；先分集再写，不写完大块故事再切集。

## 入口与必要输入

接到“写首三集”“继续下一批”“按已确认大纲写到结尾”或修订指定正文时使用。首三集就是正式开篇，不另写用完即弃的样稿。

先用 drama_agent_document 的 list/read 定位并完整读取本会话已保存项目资料，结合真实用户消息核对G3对应的全剧详纲与人物世界。资料版本和确认对象以实际回执为准，不从模板推定。原包的项目字段现仅作参考映射，具体见 [写作契约](references/modules/jubao-script-writing/writing-contract.md) 与 [宿主资料映射](references/host-records.md)。

每个新作者/新事件任务必须完整读取：

- 故事梗概、核心期待感、正式全剧总纲、全剧分集导航，以及创作契约和世界/关系/能力规则。
- 本事件资料与任务范围内每集的完整详纲，所涉人物完整小传、必要早期证据、伏笔与披露边界。
- 入口前集的实际正文和已接受状态；第 1 集用已确认开场状态。后续每集读取上一集新接受的正文与状态。
- 已确认首三集写法、人物声音和本项目人味方法。首三集尚未获 G4 时，读取现有候选写法约定，不能称其已获用户确认。

正式全剧总纲是 G3 确认的一份完整产物，含主因果、转折、关系落点与结局，不能用作者临时压缩的摘要替代。它不等于全剧所有分场详纲：任务范围外详纲按因果依赖检索原文。内部可读后续规划，角色不能因此知道未来。

输入太大时先缩小事件任务，去掉无关历史聊天；不能截断梗概、核心期待、正式全剧总纲或本任务详纲。字符阈值只是预警，不证明模型容量充足。仍放不下时交主控整理正式资料或进一步拆分，不冒称已读。

独立调用可直接承接用户明确认可的材料，不要求重走无关确认门。缺 G3 时可完善候选详纲，不冒称已授权批量正文。缺实际前集正文但已有明确入口状态时，可写有限候选并说明接缝未核查，不能作为后集的已接受事实。

## 写作与人味同时应用

先读 [写作契约](references/modules/jubao-script-writing/writing-contract.md) 和 [自含人味核心](references/modules/jubao-script-writing/human-feel-core.md)。整套技能组可用时，同时使用 [人味与情绪技能](references/modules/jubao-style-edit/method.md)，按本场问题读取其相关方法；同一作者使用两个 skill，无需额外启动一个编辑 agent。扩展方法确实无法读取时，使用已读的自含核心处理可完成范围并说明缺项，不安装其他技能或声称已加载。

写前从人物欲望与压力选择策略，写中让下一句接住刚发生的反应，写后只修实际缺陷。独立人味编辑用于具体问题段落，不默认把每集全文再写一遍。项目案例只取方法，不复制台词、角色、世界或样本错误。

## 有限事件段与本轮交付

1. 主会话按当前授权批次组织连续事件，默认三集，尾批按余数；用户明确要求更小范围时缩小。复杂段落可在本批内部拆分规划，不能以“同一事件尚未结束”扩大授权。
2. 开始前完整读取本事件与每集详纲、实际前文和必要设定，确认目的、情绪、选择/阻碍/反制/结果、信息时点与卡点。只读前置分析遵守主入口最多一次、最多两个叶子的预算，不另开执笔或润色子代理。
3. 主会话按集顺序连续写完本批，同批后集承接实际已写出的前文；未来集的预定出口不作为事实。整批核验完成前不声称任一新稿已经接受或验收，也不要求每写一集都另开审稿回合。
4. 一集包含多个小事件时仍由主会话统筹。人物能力、知情、伤势与关键物件必须在已确认来源和实际动作中成立。必要的跨集因果核对并入本次宿主核验，不叠加批末或全剧自动复查。
5. 本批正文在回复中完整流式呈现后只保存一次，名称写实际集数范围。首稿加最多一次按真实问题定向修订；未通过保留末稿，如实说明，不通过反复check或改名保存重置额度。

首批实际正文承担G4写法确认；用户未认可时不推进第4集。默认每批交付后等待“继续下一批”，这只授权下一批。用户明确要求写到结尾时可按该范围逐批推进，不重复索要已经给予的批次许可；G4、G5和未决重大变更仍按真实决定处理。用户在无待决分歧时明确接受首批并要求继续，可以依据同一实际消息记录两项含义，不要求固定口令或新增人工门。

## 创作权限

可补服务已定事件的对白、动作、现场反应、过渡、非关键场景细节、小功能角色与普通道具。不得改变主线因果、主要人物动机/关系、核心世界规则、胜负与主要结果、关键证据来源、信息揭示时点或卡点功能。小功能角色不能暗变成决定胜负的证人、秘密亲属或新能力来源。

需要重大变化时说明最小改动、理由及受影响内容，交用户决定；只暂停依赖该决定的部分。用户已经明确要求的变更直接在其范围内落实，不再索取解锁口令。格式或措辞问题按影响范围修复，不触发整集重写。

普通写作只交正常正文，必要可见动作与表演提示属于正文。导演处理在全剧 G5 后按已有授权执行，不在写作期提供双版本菜单或要求摄影参数。

## 返回与保存

首先完整输出本次实际集号范围的中文正文，沿用项目格式，使用真实换行；不混入自检表、状态字段、工具回执或流程汇报。正文默认每集1400–1600汉字，用户明确范围和统计口径优先；只有实际统计后才能报精确字数。

写完立即用 drama_agent_document(action="save", kind="script", name=实际范围, from_reply=true) 保存流式正文，不在工具参数中再次复制全文。项目档案、分析或大纲按各自类型分别交付，不把内部记录和正文合成一份。保存、Word导出和质量状态分别按本次真实回执说明。

主会话简要说明实际状态变化、与详纲的差异及仍需用户决定的问题。涉及核心新设定时按用户决定和 drama_story_bible 的提案/确认机制处理；系统suggestion不能伪装成用户确认。只读叶子只能返回发现，不写稿、状态、确认或有效版本。

候选改动要同步核对其因果与实际状态，不能靠改记录掩盖正文错误。质量由宿主现有核验链处理；按缺项最多一次定向修订，仍未通过结束本轮并保留末稿。不要另造文件路径、内容hash、接受状态、独立审读身份或导出成功回执。

## Hermes 接入边界

本篇是当前主 Agent 的内部方法。读取与交付统一按 [宿主流程](references/host-workflow.md) 和 [资料映射](references/host-records.md) 执行；创意落点按 [创意保护](references/highlights.md) 保留。主会话是唯一正文作者与保存者；原生只读前置分析最多一次、最多两个叶子。质量只走宿主同一条核验链，首稿加最多一次定向修订，不因本篇方法另起逐集、批次或全剧自动审读。项目字段模板只用于整理真实稿件与用户决定的引用，不能冒称原文件状态机或独立审核已经执行。
