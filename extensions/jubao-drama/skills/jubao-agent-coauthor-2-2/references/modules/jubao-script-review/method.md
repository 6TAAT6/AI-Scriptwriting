# 独立审核

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

明确用户本次要求的范围：结构、单集、批次、全剧或导演一致性。读取有效原文、全局梗概/期待/总纲/导航、当前详纲、人物世界/风格、实际前文状态及本次候选；缺正文只能做大纲层分析。本模块提供宿主统一核验的检查方法，不自行增加审稿模型调用。用户明确要求审读时按范围给依据与结论；没有真实不同执行者或宿主回执时不得称独立审读。

按 [证据审核方法](references/modules/jubao-script-review/review-method.md) 执行：

1. 验证版本与授权；发现旧基线候选先标待复核，不继续把它当新事实提交。
2. 对照戏剧目的、情绪曲线、卡点及主因果；阅读实际演出的戏，不只信状态表和作者创作意图。
3. 检查人物行动/关系/知情、误信、能力资源、伤势道具与伏笔连续性；未知事实不得为推进剧情被突然说出。
4. 检查对白目标、反应链、人物辨识度、口语与情绪触发、可见动作、格式和信息冗余；特别核对动作主语/受事、对象、清醒程度、声音可听范围与实际知情。按项目风格判断，不把“完整句/有效率/直接表达”判作 AI 味。
5. 按范围追加三集进展或全剧兑现检查；导演模式逐场对源定稿，查是否偷改信息揭示、关系、动机、能力和胜负。
6. 输出有文本证据的问题、影响、修复目标、是否越过已授权边界。问题数量为零也可，不能凑评委或强制分歧。
7. 只读审稿给出具体问题与修复目标，不自行改写或保存。用户同时明确要求修改时，由主会话在已授权范围内处理，重大因果/关系/规则取舍依据真实决定；已明确授权的不重复求批。核对受影响内容的方法并入宿主有限核验预算，不因格式错重写整集，不反复重审全稿。

输出简短、有原文依据的审核报告，说明候选状态是否与正文相符及未确认边界。用户只要审读时不交改稿；明确要求修改时由主会话另交授权范围的候选和差异。未发现问题不等于保证全剧质量或平台通过，也不替代G5真实用户定稿。

主会话可连续完成当前批内1–3集，先按真实详纲与前文保持因果，再使用宿主同一条稿件核验链。人味方法、客观统计和G4/G5用户决定各有范围，不互相代替，也不新增逐集接受审稿门。正文默认每集1400–1600汉字，用户明确范围和统计口径优先；不能以旧软参考允许任意超长，也不为达数损坏因果。

## Hermes 接入边界

本篇是当前主 Agent 的内部方法。读取与交付统一按 [宿主流程](references/host-workflow.md) 和 [资料映射](references/host-records.md) 执行；创意落点按 [创意保护](references/highlights.md) 保留。主会话是唯一正文作者与保存者；原生只读前置分析最多一次、最多两个叶子。质量只走宿主同一条核验链，首稿加最多一次定向修订，不因本篇方法另起逐集、批次或全剧自动审读。项目字段模板只用于整理真实稿件与用户决定的引用，不能冒称原文件状态机或独立审核已经执行。
