# 候选、人物、详纲与对照契约

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

## 一、同方向三简纲，只深化一份

G2 解决新世界、人物功能和冲突机制，G3 的三份简纲解决在该方向里怎样走到终局。三个候选粒度相近，都覆盖开篇、主要选择、关键反制与转折、关系变化、阶段期待兑现和结局，不能以“高潮待定”换取短小。每份约 500—800 字仅是方便阅读的起点，实际复杂度优先。每份另附具体亮点清单：具体机制、精彩原因、必要铺垫与代价；用户选定后把需保留项映射到详纲集/场。数量随故事需要，不凑反转配额。

比较页说明每份最有戏的路径差别、人物主动性和代价，附关键集映射验证原戏剧目的、情绪曲线、卡点能否保留。三份不能暗中换掉已定题材、世界、主关系、性别或核心期待；确需改变时列明影响并取得对应决定。未选候选不继续展开详细集纲或完整人物百科，也不混进有效设定。

用户可以选择、修改、混合、要求重生或自供。已明确选定并批准的等价简纲可直接深化；否则等待真实选择。选简纲只是 G3 内部中间决定；详细骨架仍须展示和确认。这是两次人工操作，不把两者合称一个节点后省略第二次。

## 二、人物分层与完整小传

方向与简纲阶段使用功能骨架：身份功能、欲望、恐惧、行动倾向、权力/依赖、可用资源及边界。选定简纲后，完整新人物小传与详细事件同时深化，而不是所有事件写死后再事后编动机。

每位主要人物提供连贯小传，覆盖原材料支持或新方向已设计的身份经历、欲望/需求/恐惧、性格矛盾、采取行动的习惯、主要关系与权力、资源能力/边界/代价、语言指纹、压力下的行为、关键弧光或不变原则。没有情节需要不强补身世和创伤，不要求人人九维满格。原作未知年龄或身高保持未知；新作可因设计需要明确新值，标为新设计。

语言指纹描述句长、词汇、称谓、直说/迂回/反问，以及不同关系面前的策略，不是人人固定口头禅。身体习惯有情境，不将攥拳/抿嘴自动绑定心理真相。完整小传可分文件检索，但人类阅读版不能缩成外貌职业表。

逐人记录原对应、用户同意的合并/拆分，或获准小功能新增。合并/拆分说明原功能落到哪里。小功能角色可以服务过渡、动作或日常作用，不能借其偷加主要亲缘、隐藏身份、关键解谜或决定胜负的资源。主要关系、主线因果和世界规则的额外变化属于人工决定范围；用户已明确要求的改变不重复请批。

## 三、四份全局方向资料与事件层

以下各项都是正式 G3 产物，须可独立定位、完整读取并随版本维护：

1. **故事梗概**：完整概括主角处境、目标、主线发展与结局。不是方向阶段三句话短卡。
2. **核心期待**：观众持续等待的具体结果，压力来源、蓄力方式、阶段兑现与终局承诺；不以题材标签替代。
3. **完整全剧总纲**：整条主线因果、主要人物选择和反制、关键转折、关系落点、世界机制与终局。每个新作者读取正式全文，不能临时反复压缩成接力摘要。
4. **全剧每集导航**：每集的事件归属、戏剧目的、情绪曲线、核心信息出口、关键卡点与下集承接。它帮助定位本集，不替代逐场详纲。

另建 **事件区间**，说明事件目标、起止集数、核心冲突、选择/反制、阶段结果、状态入口/出口、卡点位置与下一事件承接。事件长短来自故事，不固定成 3、5 或 10 集。实际总集数和付费点遵循本项目，不默认 45 集或固定一卡/二卡区间。

接入项目登记时，四份资料分别对应 `documents.synopsis`、`documents.core_expectation`、`documents.overall_outline`、`documents.episode_map`。事件登记为 `events` 中按 ID 定位的 `{start, end, path}`，每集以 `episodes.N.event_id` 标注主事件；同集的次事件在该集与事件正文中说明，不据此创建相互矛盾的主归属。具体字段和文件校验由总控执行，不能仅写字段名就声称文件存在。

上述资料须在内容和版本上彼此一致。完整总纲不等于把全部集的所有分场复制进一个巨大文件；保留整条因果和终局，由详纲承载执行细节。任何整理后的正式总纲都随 G3 版本更新，不能由正文作者独自截断必读内容。

## 四、每集详细纲的最低可写程度

- 保留资产：原集戏剧目的、情绪曲线、卡点功能及来源。
- 新集目标：本集谁要从谁处得到什么，承接前集什么未解决事项。
- 按场次叙述：地点/时间与人物；每方目标/策略；触发→行动→反制→选择→结果；必要信息获取路径；情绪起点/转折/出口；场与场为何相连。
- 计划状态变化：位置、知情与误信、关系、资源、伤势、道具；伏笔埋设/推进/回收及最早允许披露节点。
- 结尾卡点：实际留给观众的问题及下一集承接，不只写“此处悬念”；终集可完成承诺并收束。
- 可自由发挥的空间与不可变项。

这些是语义要求，不强迫每场填一张大表。详纲要足够可写，并给对白、动作、过渡、场景细节和获准小功能角色保留空间，不提前写成僵硬逐句台词稿。动作胜负与必要可演因果应在普通正文层成立；镜头和表演强化留待全剧定稿后的导演环节。

每集正文默认按1400–1600汉字规划信息密度，用户明确范围和统计口径优先。保留关键因果与功能，在范围内删冗余或补必要动作，不以软参考豁免字数要求；对白动作不设统一配额。详纲可按事件段制作，但全部详纲和人物资料完整后才交G3确认，后段不能退化为“升级、决战”等概要。

## 五、事件设计、作者任务与三集交付

这三种范围不同。事件层组织连续目标和情绪；分集控制观看节奏；三集是默认交付窗口。G3 必须先明确每集目的、情绪、信息出口和卡点，不能先写一个长事件再随意切集。

正文由主会话按当前授权批次内的连续事件顺序写作，通常一至三集；范围取决于实际资料与用户要求。事件跨批时保留既定集尾和实际前文，不因事件未完扩大续写授权。用户明确到结尾可逐批推进，仍保留首批G4、全剧G5和重大取舍。前置分析只读，不另派写稿或逐集审稿代理。

同一集包含多个小事件，可由同一作者统筹；全剧导航应能显示主事件及必要次事件，不为每个动作另开作者。彼此依赖的事件不能同时自由写作。详纲中的预期出口是规划，不代替前集已经写成且核验过的实际状态。

## 六、完整对照如何显示

G2 的代表片段帮助选方向；G3 交付全部主要人物和全部集，不只例子。

人物阅读版：每个映射一组“原人物完整小传｜新人物完整小传”。原侧不足注明缺失，不用新推断补原事实。合并/拆分在对应位置说明功能归属与用户同意的变化；新增功能角色单列其用途和边界。

总纲阅读版：两栏或相邻原/新块，分别展示背景年代、世界/核心规则、核心期待、完整梗概、完整主线及关键转折和终局。可以另有短比较页，但不能用它替代完整阅读内容。

逐集对照：三栏“集数｜原完整集纲｜新详细集纲”，允许分集或分页面显示但不截断正文。原作只有简纲就展示其实际完整简纲，不能编造原详纲；缺失、推断和矛盾继续标注。

若用户需要 Excel：人物表两列、分集表三列，启用换行并校验单元格全文；总纲对照放完整阅读文档或简单独立工作表。不能为表格美观缩成两句，内部 ID、评分和检索标签不塞进人类对照表。导出另遵循实际文件工具的验证要求。

## 七、核验、人工修改与提交

核验逐集保留资产、具体因果差异、所有集的可写程度、人物动机和变化、资源能力边界、信息揭示、跨事件接缝、伏笔与终局兑现。审查基于实际材料和来源，问题定位到具体内容，不以“AI 自检通过”冒充证据。

题材有不同检查重点：悬疑查线索与知情；奇幻/科幻查规则和社会后果；历史查决定事件的时代条件；喜剧查反差是否破坏动机；动作查目标与胜负原因。关系变化由事件推动，伏笔按约定窗口跟踪，不一律三集到期；金句、反转、情绪层数不设统一配额。

人工修改先检查直接改动及动机、信息、前置伏笔、资源和后续结果的依赖，只修必要范围。更新相关小传、总纲、导航、事件、详纲和对照，不能只改用户点名一句留下逻辑断层，也不因格式小错整剧重写。已确认骨架发生变化时交给总控更新版本与确认记录，旧快照不能继续作为新骨架已获确认的依据。

提交G3确认时交付完整原新对照、全局资料、全部人物世界、逐集详纲与计划状态，保留真实来源与用户决定。由主会话使用宿主稿件工具保存可读成果并引用真实ID/版本；本模块不虚构原包JSON状态、机器快照、独立审读或用户确认已经完成。

## 规则来源与使用范围

综合原技能包的故事结构、人物与集纲方法，四份新参考中的分层对照、来源映射、事件导航和核验意识，以及用户于 2026-10-16 确认的先三简纲后深化、有限事件段和字数软参考。运行规则已自包含，不依赖原附件绝对路径；附件的固定集数、任错整集重写和无条件禁止功能新增不继承。
