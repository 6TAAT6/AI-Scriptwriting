# 大纲与人物设计

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

输入原作完整事实与逐集资产、已确认 G2 方向、允许改变范围及实际集数/市场/年代要求。独立调用可使用用户明确批准的等价方向或大纲，尊重已完成的选择，不强迫重走上游。不能因附件含有“直接写到某集”就取得正文授权。

按 [候选、人物、详纲与对照契约](references/modules/jubao-episode-outline/outline-contract.md) 执行：

1. **三份全剧简纲。** 在同一选定方向内给出三个从开篇到终局的简纲，包含主要选择、转折、关系变化、期待兑现、结局及关键集映射。可先按每份约 500—800 字控制阅读量，这是建议，不是硬限额。差异落在行动、反制、资源、因果和代价，不暗换 G2 设定或逐集保留资产。
2. **用户选择。** 展示三方案实质区别，等用户选择、修改、混合、重生或直接提供。混合后先复核兼容性，只深化选中的一个。选择记录是 G3 内的中间决定，**不等于 G3 已通过**。
3. **人物与骨架共同深化。** 在功能骨架基础上完善完整新人物小传、关系、语言行为指纹及世界能力边界；与事件互相验证。形成独立可读取的完整故事梗概、核心期待、正式全剧总纲、全剧每集导航和事件区间。
4. **补齐每一集详细纲。** 写清各场任务、人物选择与反制、信息获取、情绪变化、入口/出口、卡点及下集承接；后段与前段同等可执行。可分事件段制作，但全体完成和核验前不开正文。
5. **建立计划账本。** 记录知情/误信、关系、伤势资源道具、伏笔和披露窗口，明确这是计划，不伪称正文已发生。按正文默认每集1400–1600汉字规划信息密度；用户明确范围与统计口径优先。对照戏剧目的保留必要因果，不能靠机械删戏或无效填充达数。
6. **完整原新对照。** 展示所有主要人物的完整原新小传、原新完整总纲/梗概及每集原纲与新详纲，保留原侧缺项和推断。创作时运用结构核对方法，交付后只走宿主统一核验；本模块不额外启动结构自查、独立复审或反复修订，也不以作者自报通过替代真实核验。
7. **最终 G3 确认。** 修复具体问题和受影响依赖后，交付完整骨架供用户确认。总控记录有效 outline/canon 版本、全部覆盖集数及真实文件快照。用户确认之前不安排正文批量开写。

五类内容确认保持不变：G3 内有“选简纲”和“确认完整详纲”两次人工操作，不新增人物确认门。重大取舍仍按用户实际授权处理。

交付完整阅读版、完整原新对照、人物世界主档、全剧梗概/期待/总纲/导航/事件、全部详纲和计划账本。正文作者每个新任务都读完整全局资料，并读取当前范围详纲、相关人物及实际状态；不能只传本集摘要。事件区间用于设计，有限事件执笔仍由总控按授权批次和容量划分，不能反过来改变已定分集卡点。本 skill 不写正文或导演加工稿。
