# 后段质量与连续性

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

## 诊断而不是只归因上下文

后段变差可能来自上下文干扰、摘要递归失真、后段详纲过粗、状态未同步、角色口吻趋同、输出受限或互相矛盾的规则。新 agent 只改善部分因素；没有实际日志和输入时不下“必然超上下文”的结论。

全剧骨架决定方向，有限事件任务决定一次作者范围，三集窗口决定交付与继续节奏。新的事件任务从文件恢复，不继承全部聊天；同一任务内逐集写、审、提交，跨批重新建任务。长事件沿已确定分集拆开，不因事件未完突破暂停。

## 每个新作者必须真正读取的内容

| 层 | 必要资料 |
|---|---|
| 全局 | 正式故事梗概全文、独立核心期待全文、完整全剧总纲、每集导航 |
| 当前事件 | 当前主事件目标与结果、本任务所有完整详纲、相关完整人物小传、世界关系与能力边界 |
| 实际事实 | 前集实际正文及状态、相关早期正文证据、人物知情/误信、位置/伤势/资源/道具、活跃伏笔和披露界限 |
| 写法 | 当前写法基准、已接受首批的有关原文锚、正文与人味方法、任务允许范围 |

完整总纲应包含全剧因果、关键转折、关系落点和终局。它不是全部分场详纲，但必须是同一份正式全文，不能由每位作者临时缩成三句话。局部详纲负责具体执行，两者不能相互替代。

同一事件任务内，已实际读过、仍在有效上下文中且内容指纹未变的全局文件，可核对指纹后复用，不重复把同一全文贴入聊天；当集详纲、新前驱正文和状态、发生变化的披露资料仍实际读取。新上下文、经历压缩或无法确认已读内容时重读全文，不能把文件缓存当作模型已读证据。完整资料包仍保存全文，核对与恢复有据可查。

事件计划先帮助主会话理解连续段，再按实际前文维护当前集入口；这里的资料集合来自宿主真实读取，不另生成原包脚本资料包。未来出口尚未发生时只标计划，不能伪造已接受状态。人物知情须追溯观察、告知、经历或合理推断；误信不自动成为事实。

资料过大先缩小当前任务、剔除无关历史和不适用案例；必读全文仍要保留。仍超容量则明确缺口并调整正式资料组织，不静默截断详纲或终局。字符上限只是操作预警，不涵盖所有工具/系统/输出占用，不能当作 token 保证。

## 状态与版本

计划出口来自详纲，实际出口来自正文证据。两者不一致时先判断写漏还是剧情变更，再修稿或取得具体决定，不用状态表掩盖缺戏。历史事件保留原文证据；当前状态只留仍需携带的事实，避免摘要再摘要成为唯一记忆。

G3确认对象覆盖完整全局故事资料、全部详纲、人物与事件导航，采用宿主实际稿件ID/内容指纹和真实用户消息关联。未装入本轮的后段资料在实际依赖时读取，不宣称原包全文件自动快照门禁已经运行。变更时确定影响，复核实际前文、写法和披露状态，保留无关内容，不只升级版本号或重做记录掩盖改稿。

## 审查与提速

对本轮实际候选核对目的、情绪、卡点、人物策略、信息、主语/受事/空间、伤势道具及对白反应链。这些维度由主会话创作时运用并进入宿主同一核验链，不额外启动逐集审稿、接受门或另一套复审；只读分析回传不能当成稿件验收。

批次中关注重复推进、人物声音漂移、概述式快进、阻力跳过、新能力救场、伏笔遗忘和高潮压缩；终局关注期待、承诺与关系兑现。它们是本次宿主核验的维度，不因批末或全剧阶段另开自动审读。用户明确要求全剧审读时按实际范围读取并报告，仍不无限返修。

提速来自只深化选中候选、复用仍有效的已读资料、正文与人味同用、按证据局部修订和宿主同稿回执复用。不能靠删后段详纲、忽略正文依据或压短正文假装提速；比较速度时记录同等输入和质量要求下的实际耗时。

主会话控制历史长度；只读子智能体仅返回必要发现与来源定位，不反复回传全剧。阶段结束保留真实稿件和用户决定的引用，恢复时回读有效主档；方法文件不能保证幻觉为零。
