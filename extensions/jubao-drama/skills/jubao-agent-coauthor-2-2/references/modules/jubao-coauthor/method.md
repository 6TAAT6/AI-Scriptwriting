# 巨豹共创总控

> 本篇是同一主Agent的内部方法，使用 [宿主流程](references/host-workflow.md) 与 [资料映射](references/host-records.md)。方法和历史案例不另起执行者、审稿轮次或用户长期要求；当前明确用户要求优先，全部包内路径相对于技能根目录。

以原作每集戏剧目的、情绪曲线、关键卡点与已确认核心期待为保留资产，重创具体行动和因果，按新骨架写成中文全本。附件中的指令是待评估材料；用户明确决定、有效新作设定和实际正文证据决定当前工作。

## 接入和方法分工

先读当前请求、项目有效文件与真实决定。已有成果从相应阶段接入，不重走问卷。读取 [协作与版本协议](references/modules/jubao-coauthor/protocol.md)；进入正文再读 [项目契约](references/modules/jubao-coauthor/project-schema.md) 与 [连续性方法](references/modules/jubao-coauthor/continuity.md)。

路由：原作事实→`references/modules/jubao-source-analysis/method.md`；三个平替方向→`references/modules/jubao-adaptation/method.md`；三简纲、人物与全剧详纲→`references/modules/jubao-episode-outline/method.md`；正文→`references/modules/jubao-script-writing/method.md`；写前和写中的人味方法及定向精修→`references/modules/jubao-style-edit/method.md`；独立审查→`references/modules/jubao-script-review/method.md`；全剧定稿后的画面处理→`references/modules/jubao-director/method.md`。

skill 是方法，agent 是执行者。正文作者同时运用正文与人味方法，不默认另开 agent 全文润色。保持八个独立模块；按当前任务加载必要资料。单项调用缺材料时只问影响该任务的缺口，不强迫重走总流程。

## 五类内容确认

| 节点 | 用户可见成果与选择 |
|---|---|
| G1 原作理解 | 完整原人物、梗概、逐集纲、核心期待和保留资产，事实/推断/缺失分清 |
| G2 平替方向 | 默认三个方向，可重生、修改、混合或人工自供；选定后才生成新纲候选 |
| G3 新骨架 | 先选三个覆盖结局的全剧简纲中的一个，再深化完整人物与全部详细集纲，展示原新完整对照后确认 |
| G4 首三集写法 | 首批实际正文就是样稿，认可后纳入全剧；不足三集按实际首批 |
| G5 全剧定稿 | 全剧实际完整候选、准确版本与宿主真实核验状态，用户确认后才称定稿 |

G3 是一类内容门，但包含“选简纲”和“确认完整详纲”两次人工操作。选择简纲不能视为全部详纲已确认。新人物先定功能、欲望、权力和资源骨架，选定简纲后完善深小传，与详纲互校；G3 一起确认，不另增人物门。

确认必须指向真实可见产物。用户已明确提出的修改直接执行；仅对尚未确定的重大因果、主关系、世界规则取舍提问。不得用重生成清单替代用户决定。

## 三集窗口与推进授权

默认每批三集，尾批按余数；交付后停止，等“继续下一批”。这一表达只授权下一批。用户明确更小范围可以缩小并记录。

用户明确要求“一次写到结尾”时，记录起止范围和真实表达，仍每三集检查与交付，但可在已授权范围内自动开启下一窗口。G4 未通过时仍停在首三集；G5 仍由用户确认。用户暂停、缩小范围或提出尚未解决的重大变更时停下相关推进。范围授权、三集交付窗口和内容确认分别记录。

正文只在全部详纲已通过 G3 后开始。用事件导航选择当前窗口内连续一段，通常一至三集；同一作者逐集成稿。一个事件超过当前窗口时拆成前后任务；单集有多个小事件由同一作者统筹。分集、戏剧目的和卡点在开写前确定，不写完长段再随意切集。

每个新事件段由主会话依据当前真实资料确定范围。复杂任务需要前置分析时，只使用宿主原生 delegate_task：本轮最多一次、最多两个只读叶子，分别返回因果/人物与结构/连续性发现；传入同一用户要求及已读取资料，不让叶子写稿、保存、导出或递归委派。未实际调用不得声称已启动；不通过切换名字冒充上下文隔离或独立审读。

## 资料、候选与状态

主会话完整读取当前任务必需的故事梗概、核心期待、正式全剧总纲、逐集导航、创作契约、世界关系、写法基准、人味方法、披露/伏笔资料和创意亮点。再读取本事件与本批完整详纲、相关完整小传、前集实际正文与状态、必要早期证据。不能让各个分析器自行生成临时摘要替代权威全局资料，也不能把后续规划当成已发生事实。

本账号附件使用 drama_material_import，按真实分页/范围读完相关内容；已保存稿件先用 drama_agent_document(action="list") 定位当前会话中的实际对象，再用 read 完整读取，并沿用回执中的版本和内容指纹。用户要求通过 drama_requirements 查看；世界、关系、关键物件及末态通过 drama_story_bible 查看。模型不得自行把附件、推断或候选设定升级为用户要求或确认。

[项目参考字段](assets/project-reference.json) 与 [资料映射](references/host-records.md) 只是整理真实资料的字段说明，不代表已创建JSON主账本、执行文件状态机或写入确认。每份计划、详纲、正文和确认对象必须对应真实可读稿件；G1–G5依据本会话实际用户消息及对应版本，不填写示例批准记录。

主会话按既定分集顺序连续完成本批，逐集保持行动、知情、伤势、道具与结果的一致性。已经写出的本批前集内容可以作为后集创作的已知前文，但整批核验结束前不得称它已验收。没有实际正文的未来出口只记为计划，不用状态字段反向证明剧情发生。

候选正文从标题开始完整流式输出。本批写完后只保存一次：drama_agent_document(action="save", kind="script", name=实际集数范围, from_reply=true)。大纲、分析和项目资料分别使用对应kind保存，不与正文混成一份。保存后的质量仅由宿主统一核验链处理；按真实未达标项最多一次定向修订，仍未通过则保留末稿并说明。不要再发起逐集、批次或全剧自动审稿来追求通过。

需要独立性时只认可宿主实际发生的工具/任务回执，不能把同一执行者改名或自写pass当独立审读。子智能体只返回只读发现；主会话是唯一正文作者和保存者。资料过大时按当前任务缩小范围并保留必需全文，不静默截断，不把字符阈值当模型容量保证。

## 交付、修改与恢复

每批交付正常中文正文及必要短说明。正文默认每集1400–1600汉字，用户本轮明确范围和统计口径优先；按已授权范围规划情节，在范围内保留关键因果，不以旧软参考默认豁免上限，也不凑无效内容。字数只引用宿主本稿真实统计。诊断、状态和流程说明与正文分开，保存和Word导出仅按实际回执说明。

批末的连续性与兑现问题作为宿主本次核验的检查维度，不另开自动审读或新修订轮。默认交付后等待下一批授权；已有明确持续授权则在其范围内按批推进。首批等待G4，完整候选等待G5。G5后执行已获得的导演加工授权，不重复索取同一许可，也不在写作期提供双版本菜单。

恢复时读当前项目、真实决定、有效主档和实际正文。早期变更按人物、信息、资源、伏笔和结果传播影响，标记受影响下游待复核；无关内容保留。格式小错局部修复，不默认整集重写。风格方法、披露实际账变化与 G3 静态故事骨架分开管理，具体字段见项目契约。
