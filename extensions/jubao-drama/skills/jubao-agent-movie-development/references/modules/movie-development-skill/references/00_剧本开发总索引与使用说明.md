## 2. 案例库（assets/library/）

来源为 IMDb Top 200 范围内的 160 部电影剧本（PDF 提取文本），另有 55 份剧集文本与 7 部低质来源被排除，共 222 个来源记录于 `manifest.jsonl`。

| 文件 | 用途 |
| --- | --- |
| manifest.jsonl | 222 个来源的类型、提取状态、是否入库、排除原因与 provenance |
| case_cards.jsonl | 电影/节拍/场景三层机制卡（L1/L2/L3） |
| patterns.jsonl | 按故事类型、节拍功能、场景压力提炼的跨片型模式 |
| type_stats.json | 卡片数量、类型分布与校验目标 |

卡片质量等级：每张卡带 `content_quality` 字段。`curated` 表示内容经人工撰写、对应影片真实剧情机制；`template` 表示由启发式脚本生成、仅有通用节拍定义，引用时不可当作该片的真实剧情依据。检索脚本默认对 curated 卡加权。

| 详细度 | 内容 | 质量现状 |
| --- | --- | --- |
| L1 | 电影级结构卡：故事类型、logline、主角弧光、A/B 故事、开场/终场对照 | 全部 160 部为 curated |
| L2 | 15 节拍卡：每片每节拍一张（共 2400 张） | 全部 160 部为 curated |
| L3 | 重点场景机制卡 | 全部为 template，仅供节拍定位参考 |

## 3. 本机全文库（assets/full-text/）

160 部剧本全文的混淆缓存，仅作本机深度检索用，混淆只防随手阅读、不是安全方案。该目录缺失时 skill 仍可只靠 `assets/library/` 工作。全文只提供机制分析证据；输出必须是原创结构、场景与对白。

## 4. 重建与维护

```bash
# 重建案例库（需要本机剧本缓存）
MOVIE_SKILL_CACHE_ROOT=/path/to/imdb_top_200 python3 scripts/build_library.py

# 将人工撰写的 curated 内容套用到 case_cards.jsonl
python3 scripts/apply_curated.py

# 校验与打包
python3 scripts/validate_skill.py
python3 scripts/package_skill.py --exclude-full-text
```
