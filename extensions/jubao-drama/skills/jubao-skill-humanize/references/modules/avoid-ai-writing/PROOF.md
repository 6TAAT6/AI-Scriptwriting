# 证明：本 skill 的检测器，对本 skill 自己的文字跑一遍

一个能在你的草稿里标出 "delve" 的工具，理应扛得住用它自己跑一遍。本页是
把 `detector/patterns.js` 跑在本仓库文档上的结果，包括那些不好看的发现。

一条命令即可复现，无需任何依赖：

```bash
git clone https://github.com/conorbronsdon/avoid-ai-writing && cd avoid-ai-writing
node scripts/self-scan.js
```

## 结果（v3.22.0，2026-07-31 实测）

| 文档 | 词数 | 原始分 | 豁免后分 | 预算 |
|---|---:|---:|---:|---:|
| `README.md` | 3,977 | 65 | **21** | 30 |
| `SKILL.md` | 14,008 | 89 | **12** | 25 |
| `CONTRIBUTING.md` | 527 | 3 | **1** | 15 |
| `detector/README.md` | 593 | 2 | **2** | 15 |
| `detector/CATEGORIES.md` | 1,064 | 1 | **1** | 15 |
| `CHANGELOG.md` | 7,192 | 62 | **32** | 40 |
| `PROOF.md` | 995 | 15 | **14** | 20 |

`PROOF.md` 那一行是一份快照，且带有轻微的自我指涉：编辑本页会改变它自身的
词数和分数。CI 用 `scripts/self-scan.js` 里的实时数字把关，而不是这张表的
文字，所以请把那一行视为对其所写提交准确、并以运行该命令来获取当前值。

分数从 0 到 100，0 表示干净。公布两列分数，是因为只公布好看的那一列，正是
本项目存在的意义所要批评的行为。

**Raw（原始分）** 计入每一次匹配，包括那张 112 词的词表，以及本仓库为了警示
而引用的每一条模式。`SKILL.md` 的原始分为 92，意味着这份目录里就含着它所
编录的那些词。这个数字是噪声，把它放在这里，是免得有人疑惑被压掉了什么。

**Exempt（豁免后分）** 套用 `SKILL.md` 一直在散文里说明过的自我引用逃生口：
*“引用的示例豁免于标记。位于引号、代码块内，或被明确标注为示例的文字，不应
被改写。”* 在本扫描出现之前，这条规则只是写给模型的一条指令而已。
`scripts/self-scan.js` 中的 `applyExemptions()` 是它的可执行形态：先把围栏代码、
行内代码、表格、引用块和带引号片段清空，再对剩余部分打分。

预算在 CI 中对“豁免后分”列把关。它们是从实测值留出几分余量设下的回归上限，
而非质量声明，且只会往下走。上调某一项预算，是属于在 pull request 里、并写明
新数字的决定。

## 扫描在我们自己的文字里发现了什么

有四条结果值得点名，而不是悄悄抹掉。

**1. `CHANGELOG.md` 得分最差，且其中约一半是豁免机制够不到的。** 一条宣布
新规则的变更日志，会把该规则命中的词列出来，不加引号、用逗号分隔：
*bustling, intricate, ever-evolving, daunting, holistic, actionable, impactful,
learnings, synergy, interplay*。检测器读到的是一段 Tier 1 词表连缀；而读者读到
的是一条发布说明。豁免机制只覆盖被引用或被代码块围起的文本，因此这些残留就
留在了分数里。

**2. 破折号（em-dash）规则没有为两种形态实现它自己的例外。**
`SKILL.md` 把列表项分隔符（`- **Term** — description`）作为排版而不是散文
标点来豁免，`detector/patterns.js` 也正是这么实现的。但它没有豁免两种几乎
一模一样的形态：

- Keep-a-Changelog 的版本标题：`## [3.21.0] — 2026-07-30`。`CHANGELOG.md`
  里有 32 处，每一处都被当作散文破折号计入。
- 列表项里加粗的引导词在破折号前还带着括注：
  ``- **Lingering-attention claims** (`lingering-attention`) — the share-post
  frame…``

扫描之时，`CHANGELOG.md` 里有 137 个破折号，检测器豁免了 53 个、计入了 84 个。
这 84 个里有 33 个属于上面两种形态。

已在 [#67](https://github.com/conorbronsdon/avoid-ai-writing/issues/67) 中
**修复**：两种形态现在都成了例外，并有 fixture 钉死了这一狭窄范围——标题内部的
散文破折号仍计入，因为 `SKILL.md` 对标题也适用破折号规则。正是这次扫描把它
暴露出来，而这恰恰是“要有这次扫描”的论据。

**3. 本页就在表里，并且它得了 14 分，原因正如它刚刚描述过的那样。**
`PROOF.md` 上几乎每一次命中，都来自上两段那段斜体的 Tier 1 词列表。斜体不是
豁免片段；引号、代码、表格和引用块才是。这一页解释说“发布说明因为点名模式
而触发了检测器”，结果它自己就因为点名模式而触发了检测器。其中一条命中是
真的——表格上方那一段里的一个 "in order to"，现已改成 "to"。

**4. `README.md` 的 21 分，对一个“在卖东西”的页面来说，是诚实的数字。**
残留的是广告腔（promotional register），而不是词表。这是项目 README 预期之中
的失败模式，而 `SKILL.md` 里的容忍矩阵对它一丝一毫都不放松。

## 本页不主张什么

低分只意味着这段文字不携带任何表层模式命中。它不代表写得好，也不代表是人写的。
检测器测量的是 `SKILL.md` 中可被正则检出的那部分，外加少数几个计量文体学
（stylometric）信号。散文可以是空洞的、结构上千篇一律的，并且完全不带任何痕迹。

本扫描还有一个值得说明的已知局限：清空豁免片段会轻微改变那些按全文计算的
文档级指标（破折号率、类符形符比（TTR）、加粗短语数），因为分母变小了。
词表和短语类别不受影响。

误报率（false-positive rate）已经测过，这里并不把它当作一条主张引用。
[`corpus/README.md`](corpus/README.md) 公布了针对 875 段人类段落和 779 段机器
段落的完整表格：在 `score >= 5` 时，4.2% FPR（95% CI 3.1–5.8）对 7.2% TPR。
按段落汇总的 ROC-AUC 是 0.501——等于抛硬币——文档级为 0.623。说白了，综合
分数无法可靠地把机器文本和人类文本分开，而且其上无论设什么阈值，都无法在可
容忍的误报代价下换来有用的真阳率。

这些数字之所以留在语料库说明里、而不被抬成头条，是因为它们过不了本仓库自己的
发表门槛。该门槛要求每一个主张单元格都要带 n >= 100、一个置信区间，以及不止
一种人们如今真正在写的语域（register）。当前这轮跑了前两条，却**在语域这条
上彻底失败**：HC3 只有 ChatGPT，RAID 是另一种任务形态，两者里没有任何一个是
现代指令微调模型在写一篇 LinkedIn 帖子。基于 2022–2024 助手文案测得的率，是
对当前模型表现的一个上界，而不是对它的估计。

修复这一点的入口已经开放：如果某条规则在人写的文字上误报，
[误报报告](https://github.com/conorbronsdon/avoid-ai-writing/issues/new?template=false_positive.yml)
表单会收集触发规则的最短文本、语域、这段文字实际上是怎么写的，以及它能否
成为一条公开的 fixture。语域才是关键字段，因为误报率在博客、文档、学术和聊天
散文之间并不均匀，而一个掩盖了这种离散度的单一数字，比没有数字是更糟的主张。

## 在 CI 中

`.github/workflows/detector-test.yml` 会在每次触及检测器或文档的 push 上运行
`node scripts/self-scan.js --check`。一份文档一旦漂过它的预算，构建即失败。
