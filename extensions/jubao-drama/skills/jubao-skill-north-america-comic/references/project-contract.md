# 项目状态与语言适配

项目契约是一份当前会话内可回读的内部稿件，不新建后台数据库，不猜服务器目录。所有值有来源：用户明确选择、已确认稿件或尚待确认；推荐值不能伪装成用户决定。

## 分开的字段

- `target_market`：目标市场，北美项目明确记为 `North America`，约束文化、人物、制度、命名、幽默和冲突逻辑可信。国家、年龄和平台仅在影响本轮决策时细化，不能默认所有北美受众都是美国人。
- `script_language`：剧本语言，默认 `简体中文`，覆盖正文、场景、动作、调度与工作稿；中文对白、OS、VO也可以完整保留，不因目标市场北美而翻译。
- `dialogue_language`：对白及OS/VO、旁白、画面文字，默认 `中文`，用户明确选择英文或双语时再采用该选择。保留现有“仅中文／双语”模式，不从提示词语言推断。
- `prompt_language`：图片、关键帧和视频可复制提示词使用的语言，单独记录；未明确时写“待指定”，本轮不做提示词时无需为此打断正文。用户选英文提示词时只改变提示词，不改变剧本或对白。
- `worldSetting`：已定世界，例如“海盗海洋架空世界”；时代、超自然规则、社会制度单列在设定中。
- `workingLanguage`：团队说明和设定的工作语言，如 `zh-CN`，不代替剧本、对白或提示词字段。
- `artStyle`、`medium`：美术与静态漫剧／动态漫画／AI视频分别记录；不从真人感美术反推实拍。
- `episodeCount`、`episodeWordRequirement`、`episodeDuration`：分别保存用户目标、计数口径和适用集数；未要求时保持未指定。原包60–90秒不是硬上限。
- `confirmedCanon`：人物、船名、关系、规则、已发生事件；每项指向确认稿件版本。
- `rejectedPremises`：记录拒绝内容、语义机制、用户依据、适用范围；同义改名仍受约束。
- `writingOwner`、`currentScriptVersion`、`currentStage`、`requestedRange`：一份正文版本一个负责人，阶段和范围不代替验收。

兼容旧字段时，`targetMarket=north-america` 对应 `target_market=North America`，`dialogueLanguage=zh-CN` 对应 `dialogue_language=中文`；旧 `workingLanguage=zh-CN` 只说明工作语言，不足以推断 `prompt_language`。读取已有契约时保留用户已经明确的剧本／对白选择，为缺失的 `script_language` 采用本技能简体中文默认，生成提示词语言保持待指定。新旧字段冲突时按用户最新明确决定统一，不同时保存矛盾值。

例如“北美受众、海盗海洋架空、中文剧本、仅中文对白、英文图片视频提示词、每集不少于1000字”是合法组合。不要把目标受众变成现代美国地理，不要自动翻译正文，也不要删除剧情合理的华人角色。中文只是表达语言，不撤销北美文化逻辑或用户已要求的去中国化审查；不能由此恢复已拒绝的船名、身体观念或解毒机关。

## 契约模板与三项展示

测试开始、切换语言或交接资产时，面向用户分别显示：

目标市场：北美；剧本语言：简体中文；生成提示词语言：英文。另列对白模式：仅中文；故事世界：海盗海洋架空。

以下是**用户已明确这些选择时**可保存的内部契约示例；`prompt_language=英文`不是本技能擅设的默认值：

```json
{
  "target_market": "North America",
  "script_language": "简体中文",
  "dialogue_language": "中文",
  "prompt_language": "英文",
  "worldSetting": "海盗海洋架空世界",
  "workingLanguage": "zh-CN",
  "episodeWordRequirement": "每集正文不少于1000字，按工具实际统计口径核验",
  "rejectedPremises": ["海皇身世", "神格觉醒", "同类皇族或神性血统获力机制"],
  "writingOwner": "当前已选主Agent；未选主Agent时由本独立技能的正文负责人承担"
}
```

用 `kind=internal` 保存并按稿件ID回读该记录，只能证明这些字段被结构化记录与读取，不能宣称模型已经完成北美文化适配、文学审稿或图片视频制作。英文提示词产物仍须逐项引用中文确认稿中的角色、船名、伤势、道具、动作和对白，不为提示词流畅擅改正文。

## 上游枚举的唯一适配解释

上游 `mode` 只有 `overseas | domestic`，`languageMode` 只有 `overseas-en-dialogue | domestic-zh`。旧文档中的 `languageMode=overseas` 是错误写法，必须解释为 `languageMode=overseas-en-dialogue`，不能创建第三个枚举。已适配的审稿路由在 `qc-routing.md`，原始文件保留用于追溯。

这些只是兼容上游资料的派生码，不能替代独立的市场、剧本、对白、提示词及世界字段：

- 中文对白对应 `languageMode=domestic-zh`，即使 `target_market=North America`、`mode=overseas` 仍然成立；历史词“domestic”在此只表示全中文呈现，不意味着中国市场或中国世界观，也不控制提示词语言。
- 英文对白或明确要求的中英双语对应 `languageMode=overseas-en-dialogue`；具体是否附中译仍服从用户指定的 `dialogue_language` 与呈现方式，不因上游默认值强制加译文。`prompt_language=英文`本身不会触发该枚举。
- 任何“海外就必须英文”或“中文就是国内”的上游条款都不用于当前项目。

## 决定与回退

已拒绝机制不能只删关键词。将“海皇身世、神格觉醒”抽象为“主角凭隐藏皇族／神性血统获力”的禁用机制后，“海灵皇脉嫡传”也属于同一类；普通技能成长、装备获益是否允许应依据用户已给的替代方向，不擅自新增。

用户明确改变决定时更新契约并标出受影响的集数和资产。只改措辞不重开确认；变更故事根本设定时不能依靠内部自评宣布用户已接受。十集单元闭环检查本单元目标、代价与兑现，不把分段写作当成增设新世界体系的授权。

检查状态只记录实际做过的范围。上游变更后标记受影响下游待复核；下游发现共享事实冲突时交给正文负责人处理，不能自行改世界观后反写“已确认”。
